## 二、M3-02 自动种子 bug（真 bug，已修 + 已建守卫）

### 缺陷

`apps/api/domains/portfolio/service.py`：

- `portfolio_snapshot()`（GET `/portfolio`）首行调 `repository.seed_holdings(CONFIG["holdings"])`
- `watchlist_snapshot()`（GET `/market/watchlist`）首行调 `repository.seed_watchlist(CONFIG["watchlist"])`

在**全新数据库**上，用户第一次打开页面就会把 `configs/portfolio.yaml` 的演示持仓
（茅台 600519 / 宁德 300750 / 五粮液 000858 / 比亚迪 002594 / 平安 601318）和默认自选
（NVDA / AVGO / 600036 / BTC-USDT）**真实写库**——违反「首次启动保持空数据库」。

### 修复

删除这两行播种调用（`git diff` 净 -2 行），快照函数改为只读。

### 守卫（含反向验证）

新增 `tests/test_no_autoseed.py`，3 例：service 级 ×2 + `TestClient` 端到端 GET ×1。

新增 `tools/verify_no_autoseed_guard.py`：自动注回 bug → 跑 → 按字节还原源文件 → 再跑。
证据 `docs/Plan/evidence/M3-02-autoseed-guard.json`：

run_with_bug_reintroduced      : 3 跑 / 3 失败

### 过程中踩到的两个「假通过」陷阱（已写进用例注释）

1. **模块级 `def test_*()` 不会被收集。** 门禁走 `unittest.TestLoader.discover`，只认
   `TestCase` 子类的方法。第一版写成模块级函数 → `Ran 0 tests` + `OK`，看着像通过。
2. **`app_meta` 一次性闸门。** `seed_*_if_empty` 先查 `holdings_seeded` / `watchlist_seeded`，
   命中即返回；而 `reset_holdings([])` 本身就会置位这两个键。只清表不清键，
   **无论修没修都会通过**。第二版用 `_simulate_fresh_install()` 同时清表清键才复现出真实条件。

第 2 点直接推翻了我修复前的口头结论——如果不做反向验证，这个「已修复」是没有证据支撑的。
