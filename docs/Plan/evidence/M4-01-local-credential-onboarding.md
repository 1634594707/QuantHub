# M4-01 本地安全凭据录入设计约束

- 状态：`blocked`，本地录入与只读连通测试已实现；等待真实 OKX Demo 验证和交易权限阶段验收
- 适用范围：本地单用户 QuantHub、OKX Demo Trading
- 目标：用户在“设置 / OKX 连接”中填写一次 API Key、Secret Key 和 Passphrase；后端加密保存，Runner 使用，前端永远不能取回原文
- 非目标：本项不开放 OKX Live，不替代 M4-02~M4-08 的账户规则、订单、恢复、对账和连续观察验收

## 1. 用户流程

1. 用户进入“设置 / OKX 连接”，环境固定显示为 `demo`。
2. 页面一次性提交 `API Key`、`Secret Key`、`Passphrase`；不得写入 URL、浏览器存储、表单草稿、埋点或错误日志。
3. 统一 API 校验请求来源与本地权限，把凭据交给本地凭据服务加密保存。
4. Runner 以同一 Windows 用户身份读取并解密凭据，执行只读连通性、权限和账户模式检查。
5. 页面只返回并展示：`configured`、环境、Key 指纹或尾号、权限摘要、最后验证时间、验证结果和凭据来源类型。
6. Secret Key 和 Passphrase 提交成功后永不回显；修改或轮换时必须重新输入完整三件套。
7. 用户可以显式执行“验证连接”“轮换凭据”“删除凭据”；删除后 Runner 立即停止创建新单并进入安全状态。

## 2. 本地存储边界

- Windows 桌面模式优先使用 Windows Credential Manager，或使用 DPAPI `CurrentUser` 作用域加密。
- 加密载荷放在当前用户的本地应用数据目录，例如 `%LOCALAPPDATA%/QuantHub/secrets/`，并限制为当前用户可读。
- 凭据不得进入 Git 工作区、`.env`、前端构建产物、`localStorage`、`sessionStorage`、IndexedDB、普通 SQLite 业务表、审计正文或常规数据库备份。
- 将密文复制到其他 Windows 用户或其他机器后必须无法解密；卸载、备份和迁移流程不得把密钥当普通项目数据导出。
- API 与 Runner 只绑定本机地址；浏览器不得直接访问 Runner，也不得获得 Runner 内部认证令牌。

## 3. 凭据来源规则

- 桌面本地模式默认来源为 `local_vault`。
- 环境变量只作为无界面部署的显式备选来源 `environment`，继续支持 `OKX_API_KEY`、`OKX_API_SECRET`、`OKX_PASSPHRASE`。
- 每次启动只能选择一个凭据来源；存在两个来源时必须拒绝启动或要求明确选择，禁止静默覆盖和回退。
- 状态接口可以返回 `credential_source=local_vault|environment`，但不得返回路径、密文、完整 Key、Secret 或 Passphrase。
- Demo 与 Live 使用不同的存储项、数据库和审批门禁；M4-01 只允许写入 Demo 项。

## 4. OKX 侧最低要求

- 使用独立 OKX Demo 子账户或专用模拟账户。
- 首次连通测试可只开“读取”；进入 M4 下单验收前再增加“交易”，始终禁止“提现”。
- 配置运行机器的公网出口 IP 白名单。
- 初始产品范围继续限定为 `BTC-USDT-SWAP`、限价单和撤单。
- 创建或轮换凭据后，先验证权限、账户模式、持仓模式和交易规则，未通过时不得进入下单验收。

## 5. 安全与可观测性

- 凭据录入接口必须要求本地认证、受信 Origin/Host、CSRF 防护、请求大小限制和频率限制。
- 凭据字段禁止进入访问日志、异常堆栈、审计详情、遥测、截图和前端错误边界。
- 审计只记录操作者、动作、环境、Key 指纹、成功/失败、错误码和时间，不记录秘密值。
- 所有连接异常使用稳定内部错误码；不得把 OKX SDK/CCXT 请求头、签名或原始凭据写回页面。
- 发生解密失败、权限变化、IP 不匹配或凭据失效时，Runner 必须拒绝新单，并保持撤单/停机的安全处置能力。
