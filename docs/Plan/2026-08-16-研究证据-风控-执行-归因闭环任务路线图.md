## 一、结论与目标

当前优先级不是继续增加分析算法，而是修复以下链路中的断点：

```text
研究证据 -> 统一决策 -> 服务端风控 -> 订单与成交 -> 账本 -> 收益与费用归因
```

本路线图分为两个阶段：

- [x] 第一阶段关闭四个 P1 风险：模拟风控失败开放、研究方向冲突被掩盖、交易成本档案未贯通、研究身份在账本中丢失。
- [x] 第二阶段完善四个 P2 能力：个股基本面与因子融合、历史股票池批量维护、完整订单能力、历史差异报告。

最终目标：任何可执行结论、订单、成交和收益都能恢复其研究证据、决策状态、风险判断、成本档案和归因身份；任一关键证据不完整时，系统失败关闭。

## 二、实施原则

- [x] 失败关闭：行情、账户、成本或研究证据缺失、过期、冲突时，不得创建新增风险的订单。
- [x] 服务端裁决：前端预览只用于解释，创建接口必须使用当前服务端数据重新执行风控。
- [x] 单一决策对象：价格结构、模型共识、量化快照、新闻和因子证据先归一，再生成报告文字。
- [x] 单一成本真值：研究、验证、模拟和交易消费同一版本化成本档案，不再以孤立 `commission_bps` 充当完整成本模型。
- [x] 身份不丢失：研究运行、因子、策略、信号、订单、成交和账本记录之间使用稳定 ID 关联。
- [x] 不新建重复一级页面：遵守 `docs/FUNCTION_BOUNDARIES.md`，扩展综合评估、因子验证、模拟交易、账户账本等既有归属。
- [x] 历史记录不可静默改写：契约升级通过版本字段、兼容读取和显式迁移完成。
- [x] 状态与文案分离：程序状态由确定性规则产生，展示文案不得覆盖冲突、过期或门禁失败。

## 三、目标状态与共享契约

### 3.1 统一研究决策对象

- [x] 定义 `ResearchDecision` 或等价契约，至少包含：
  - `direction`: `long | short | neutral | conflicted | insufficient`
  - `execution_eligible`: 是否允许生成执行性描述或进入信号审核
  - `module_opinions`: 各模块归一化方向、置信度、证据时间、状态和原因
  - `conflicts`: 方向冲突模块、冲突类型和阻断原因
  - `invalidation_conditions`: 失效条件
  - `reevaluate_triggers`: 重新评估触发条件
  - `decision_version`: 决策规则版本
- [x] 报告、历史比较、信号生成和执行入口消费同一决策对象，不各自推导方向。

### 3.2 风控快照与决定

- [x] 定义不可混淆的 `RiskSnapshot` 与 `RiskDecision`：
  - 行情时间、账户快照时间、价格来源和新鲜度
  - 现金、持仓、单笔仓位、总敞口、订单后敞口
  - 适用成本档案、交易约束和拒绝原因
  - 决策时间、规则版本、输入指纹
- [x] `preview` 与 `create` 可以共享风控函数，但 `create` 必须重新取数、重新计算并持久化最终决定。

### 3.3 成本档案引用

- [x] API 使用 `cost_profile_id`、`cost_profile_version` 或不可变快照引用，不再只传单一 bp 数值。
- [x] 成本档案至少覆盖：市场、标的或品类、账户范围、生效区间、来源、费用、点差、滑点、资金费率、整手、价格步长、涨跌停、容量和其他执行限制。
- [x] 研究结果保存成本档案快照哈希，保证历史结果可复现。

### 3.4 归因身份链

- [x] 统一保留以下可空但不可覆盖的身份：
  - `strategy_id`、`strategy_version`
  - `factor_key`、`factor_version`
  - `research_run_id`
  - `signal_id`
  - `simulation_order_id`
  - `execution_id`、`ledger_entry_id`
  - `market_regime_id` 或成交时市场状态快照
- [x] `source` 只表示事件来源类型，不再承担因子、策略或研究归因维度。

## 四、第一阶段：P1 闭环修复

### RISK-01 模拟订单风控失败关闭

**问题**

模拟预览在价格不可用时返回 `risk_evaluated=false` 但仍允许提交；创建接口不重新执行完整风控，手工订单与信号转单路径不一致。

**任务**

- [x] 提取模拟订单统一风控服务，供预览、手工创建和信号转单调用。
- [x] 为行情定义明确的新鲜度阈值；缺失、过期、质量失败或不可执行价格全部拒绝。
- [x] 为账户快照定义新鲜度阈值；现金、持仓或未完成订单状态过期时拒绝。
- [x] 创建接口重新读取行情与账户，重新检查现金、单笔仓位、总敞口、订单后敞口和交易约束。
- [x] 创建接口忽略前端提交的 `can_submit`、价格预览和风险结论，仅接受订单意图。
- [x] 手工模拟订单与信号转单使用相同输入契约和风控路径。
- [x] 与 `/trading` 的失败关闭语义、错误码和审计字段对齐。
- [x] 持久化最终 `RiskDecision`，使拒单和放行均可审计。
- [x] 前端在 `risk_evaluated=false`、快照过期或任一阻断项存在时禁用提交。

**验收标准**

- [x] 行情缺失、行情过期、账户快照过期时，预览和创建都返回不可提交。
- [x] 预览通过后行情、现金或持仓发生变化时，创建接口按最新状态拒绝。
- [x] 绕过前端直接调用创建接口不能绕过风控。
- [x] 手工订单和信号转单对同一订单意图产生一致的风险结果。
- [x] 拒绝响应包含机器可读原因、数据时间和重新评估动作。

**重点测试**

- [x] 服务单测：缺价、陈旧价、陈旧账户、现金不足、仓位超限、总敞口超限。
- [x] 并发回归：预览后账户变化、重复创建、幂等键重试。
- [x] API 测试：直接创建、信号转单、手工订单三条路径。
- [x] 前端测试：阻断态不可点击，错误原因与服务端一致。

### DEC-01 跨模块方向冲突与执行门禁

**问题**

个股报告优先采用模型共识方向，未比较独立价格结构方向；方向相反时仍可能生成“共同指向”类结论。止盈价标签也未根据方向变化。

**任务**

- [x] 建立模块方向归一化函数，将各模块映射为 `long | short | neutral | insufficient`。
- [x] 把价格结构、模型共识和其他可用模块全部写入统一决策对象。
- [x] 定义冲突矩阵：多空直接冲突、方向与中性不一致、证据不足、证据过期。
- [x] 任一有效模块出现反向意见时，最终方向设为 `conflicted`。
- [x] `conflicted` 或 `insufficient` 状态禁止生成入场、加仓、止损、止盈等执行性描述。
- [x] 报告明确展示各模块意见、冲突原因和需要补充的证据。
- [x] 信号生成与转单入口校验 `execution_eligible`，不能只校验展示文案。
- [x] 关键价位使用语义字段或按方向生成标签；做多止盈显示上方目标，做空止盈显示下方目标。
- [x] 历史记录保存 `decision_version`，避免新规则静默改写旧结论。

**验收标准**

- [x] 价格结构看多、模型共识看空时，报告固定显示“方向分歧”。
- [x] 冲突状态下不出现“共同指向偏强/偏弱”等一致性措辞。
- [x] 冲突状态无法生成执行信号或转换为模拟订单。
- [x] 做多、做空和观望场景的关键价位标签与几何关系正确。
- [x] 单个模块失败或过期时，报告展示证据不足，不以剩余模块伪装成全体共识。

**重点测试**

- [x] 决策表单测：`long/short/neutral/insufficient` 全组合。
- [x] 报告快照测试：冲突、一致、证据不足和过期场景。
- [x] 信号门禁集成测试：冲突结论无法进入执行。
- [x] 前端测试：关键价位标签按方向变化。

### COST-01 完整成本档案贯穿研究与验证

**问题**

因子工厂固定提交 `commission_bps=3`，证据中的成本版本由数值拼接；现有完整成本档案没有进入单标的、横截面、因子工厂和交易验证契约。

**任务**

- [x] 盘点 `core/trading_costs.py` 的档案字段、覆盖市场和当前调用方。
- [x] 定义不可变成本档案选择与快照契约，明确默认、覆盖和缺失规则。
- [x] 后端研究 API 从单一 `commission_bps` 迁移为成本档案引用。
- [x] 前端 API 类型和表单支持选择或展示适用成本档案，不再固定 `3 bp`。
- [x] 单标的研究、横截面研究、因子工厂、策略实验和交易验证消费同一成本快照。
- [x] A 股纳入印花税、佣金、过户费、整手、涨跌停和停牌约束。
- [x] 美股纳入点差、佣金、SEC/FINRA 等适用费用和公司行为约束。
- [x] OKX 纳入账户费率、点差、滑点、资金费率、数量与价格步长。
- [x] 成本档案保存来源、抓取或录入时间、生效区间、市场、适用范围和执行约束。
- [x] 成本档案不完整、过期或与市场不匹配时，不得进入 `trading_validated` 或等价状态。
- [x] 保留旧 `commission_bps` 的显式兼容读取，但标记为不完整档案，禁止升级交易状态。

**验收标准**

- [x] 新建研究不再由前端写死 `3 bp`。
- [x] 同一研究记录可恢复完全相同的成本快照和计算结果。
- [x] 修改当前成本档案不会改变历史研究结果。
- [x] 不完整成本档案可以用于草稿或探索，但不能进入交易验证状态。
- [x] 费用、点差、滑点、资金费率和执行限制会改变成本后收益、成交或门禁结果。

**重点测试**

- [x] 契约测试：档案选择、版本、生效区间、市场与账户匹配。
- [x] 市场测试：A 股、美股、OKX 各至少一个完整和一个缺失案例。
- [x] 回归测试：旧记录可读取但不会被误判为完整成本验证。
- [x] 端到端测试：研究创建至交易验证全链路成本哈希一致。

### ATTR-01 研究身份与账本归因贯通

**问题**

模拟订单已保存因子和研究身份，但同步到账本时仅写固定 `source=simulation`；账本又按 `source` 聚合，导致不同因子、版本、研究运行和策略的收益被合并。

**任务**

- [x] 扩展模拟成交、账本成交和归因记录的身份字段。
- [x] 同步到账本时透传策略、因子版本、研究运行、信号和模拟订单关系。
- [x] 为历史数据设计显式迁移；无法恢复的身份标记为 `unknown`，不伪造映射。
- [x] 保留 `source=simulation` 作为来源类型，同时增加独立归因维度。
- [x] 账本绩效支持按因子、因子版本、研究运行、策略、信号和市场状态分组。
- [x] 输出毛收益、费用、净收益、持仓时间、胜率、回撤和费用侵蚀。
- [x] 定义多身份订单的归因规则；一个成交不能被重复计入总收益。
- [x] 从归因结果提供稳定回链，可返回原研究、信号、订单和成交。
- [x] 同步失败、字段缺失和重复同步写入审计与故障聚合。

**验收标准**

- [x] 两个不同因子产生的模拟成交在账本中可分别汇总。
- [x] 同一因子的不同版本和研究运行可分别比较。
- [x] 分组净收益合计与账本总净收益一致，不重计、不漏计。
- [x] 每笔归因结果可回链到原研究、信号、模拟订单和成交。
- [x] 历史未知身份单独展示，不并入任一已知因子或策略。

**重点测试**

- [x] 迁移测试：新旧账本记录、空身份、部分身份和重复同步。
- [x] 守恒测试：各维度分组汇总与账本总额一致。
- [x] 版本测试：同因子不同版本不合并。
- [x] 前端测试：筛选、回链、空状态和未知归因展示。

## 五、第一阶段里程碑与顺序

| 里程碑 | 工作包 | 依赖 | 完成定义 |

### TRD-01 交易工作台完整订单能力

- [x] 品种选择来自账户与交易所可交易目录，不再固定单一合约。

**验收标准**

- [x] 修改订单发生行情或账户变化时重新风控。
