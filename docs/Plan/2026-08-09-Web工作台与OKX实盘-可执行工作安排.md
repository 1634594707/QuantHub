# QuantHub Web 工作台与 OKX 实盘可执行工作安排

**版本：** 1.2
**适用：** QuantHub 主 Web 工作台、统一 API、无 UI 的 OKX Runner
**起算：** T0 = 本安排获负责人确认的当日
**最近更新：** 2026-08-10（M4 前工程验收、追溯契约、浏览器与生命周期证据同步）
**目标：** 以现有 React 工作台、FastAPI 网关和 OKX Runner 为底座，在 10 至 12 周内验证一条“真实行情与研究 → 信号审核 → 风控下单 → OKX 回报 → 账实对账 → 可追溯复盘”的受控闭环。

> **使用铁律：** 每个结论和状态必须可核验、可追溯到真实证据。证据包括 commit、构建标识、测试输出、URL 返回、数据库记录、Runner 审计事件、OKX 外部订单号和对账报告。禁止以页面截图、按钮可点击或接口 HTTP 200 单独证明交易链路完成。

## 1. 结论与边界

1. 本项目不是从零开始。当前已经具备 `web/` React 工作台、`apps/api` FastAPI 网关、行情与研究能力、模拟订单与账本，以及 `apps/okx_runner` 的订单状态机、风控模式、幂等、恢复和对账基础；这些是本次工作的底座，不重写。
2. 本次只选一个主场景：用户从 `http://127.0.0.1:5173` 进入唯一 Web 工作台，查看真实数据、审核信号，并通过统一 API 将受控订单交给 OKX Runner。该场景直接服务“单工作台 + 无假数据 + 可接 OKX 实盘”的目标。
3. 平行线只保留 OKX `shadow/demo` 验证。完成凭据安全、订单恢复、账实对账、Kill Switch 和连续 Demo 验收前，不开放 `live`。
4. 本阶段不做以下事项：
   - 不恢复已删除的 Stock、Factor Lab、Product Portal 独立产品。
   - 不新增第二套前端、第二个公开 API 或浏览器直连 OKX。
   - 不同时支持现货与永续两套首期交易语义。
   - 不让 AI 直接创建或批准实盘订单。
   - 不在账实不一致、数据来源不明或风控未通过时扩大实盘额度。

## 3. 产品与架构定阵

### 3.1 唯一主场景用户旅程

> 用户需求：“我只进入一个 Web 工作台，看到真实数据，审核策略信号，安全地下单到 OKX，并能确认订单、成交、资金和持仓都对得上。”

1. **查看与判断**：选择标的，查看真实行情、研究证据、来源时间和数据状态。
2. **信号审核**：查看策略版本、信号原因、目标仓位和剩余风险，人工接受或拒绝。
3. **订单意图**：生成不可重复的订单意图，明确账户、环境、品种、方向、类型、数量和价格。
4. **风险决策**：服务端使用真实账户快照和交易所规则执行风控，保存允许或拒绝证据。
5. **受控执行**：统一 API 将订单交给 Runner，Runner 使用幂等键调用 OKX。
6. **状态恢复**：订单状态以 OKX 回报为准；超时、断线和重启后按外部订单恢复，禁止盲目重下。
7. **账实对账**：订单、成交、余额和持仓定时核对；差异未关闭时进入 `cancel_only/halted`。
8. **复盘追踪**：从任一订单追溯策略版本、信号、确认、风控、外部订单号、成交、费用和对账结果。

### 3.2 首批节点

| 节点 | 输入 | 输出 | 失败处理 | 现有能力复用 |
| --- | --- | --- | --- | --- |
| `market.snapshot` | 标的、周期、请求时间 | 行情、来源、观测时间、新鲜度 | 显示空状态、过期缓存或错误码 | `core.data_feed`、市场 API |
| `strategy.signal` | 策略版本、行情快照 | 信号、理由、目标仓位、证据引用 | 标记失败，不创建订单意图 | 策略注册、信号域 |
| `order.intent` | 已审核信号、账户、订单参数 | 唯一意图和 `client_order_id` | 重复请求返回原意图 | 信号审核、Runner 幂等 |
| `risk.decision` | 订单意图、账户快照、交易规则 | 允许/拒绝、计算过程、限制快照 | 拒单并审计，不调用交易所 | Runner 风控决策 |
| `execution.order` | 已通过风控的订单意图 | 本地订单、OKX 订单号、状态事件 | 查询恢复，禁止超时盲目重下 | Runner 状态机、CCXT 适配器 |
| `account.reconcile` | 本地账本、OKX 快照 | 差异列表、处置状态、风险模式 | 自动 `cancel_only/halted` | Runner 对账与风险模式 |

**节点通用契约：** `request_id`、`actor_id`、`account_id`、`environment`、输入版本、输出版本、策略版本、权限范围、状态、错误分类、`observed_at`、数据来源、审计事件。所有外部下单和撤单调用必须具有稳定的 idempotency key。

### 3.3 组件归属

- **保留在主 Web：** 总览、市场研究、策略、交易、账户风控、系统设置，以及统一加载/空/错/过期状态。
- **保留在统一 API：** 浏览器认证、业务聚合、研究和信号、交易代理、Runner 服务认证、错误映射和统一审计。
- **保留在 OKX Runner：** OKX 凭据、订单状态机、交易规则、下单撤单、私有数据同步、风险决策、恢复和对账。
- **不可直接共享：** 浏览器不得读取 Runner 数据库或交易凭据；API 不得绕过 Runner 直接调用 OKX；研究域不得写入真实成交和账户快照。
