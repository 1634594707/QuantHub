## 一、目标与非目标

### 目标

- [ ] 可以实时的数据使用真实实时接口，同时明确区分实时报价、未收盘 K 线和已收盘研究 K 线。
- [x] 收窄因子工厂操作区，降低横向扫描成本，同时保留密集研究结果的可读性。
- [ ] 提升 AI 候选的经济逻辑、结构差异、成本后质量和可证伪性，不只生成相邻参数变体。
- [x] 每个进入模拟观察的因子自动创建同期评估 cohort，并运行版本固定的常见策略基准池。
- [x] 候选因子、每个基准策略和每种资金管理方案分别使用独立虚拟账本。
- [x] 将网格、趋势、突破、均值回归、定投、随机信号、马丁等策略纳入公平对照。
- [x] 区分因子信号、交易策略和资金管理的贡献，禁止把行情顺风、杠杆或资金管理收益误判为因子质量。
- [x] AI 基于完整证据提出保留、淘汰或申请小额实盘的意见，但不能绕过程序和人工门禁。
- [ ] 为每个因子保存从生成、研究、同期模拟、AI 评审、人工审批到实盘表现的完整档案。

### 非目标

- [x] 不使用未收盘 K 线生成可执行因子信号，避免重绘和前视偏差。
- [x] 不让 AI 自行修改统计结论、风险阈值、确认集结果或实盘开关。
- [x] 不把马丁、网格或任何单一策略视为通用真值基准。
- [x] 不在同一个交易所净额账户中同时运行多个需要独立归因的对照策略。
- [x] 不因候选因子绝对盈利就认定有效；必须考察同期超额表现和风险预算。

## 二、统一概念与评估结构

### 三层对象

| 层级 | 定义 | 示例 |
| --- | --- | --- |
| 因子层 | 预测方向或状态的信号，不直接包含完整资金管理 | 趋势、动量、反转、量价背离、波动率、流动性 |
| 策略层 | 把信号、入场、退出和再平衡组成完整规则 | 均线、突破、固定网格、自适应网格、定投、买入持有 |
| 资金管理层 | 决定仓位规模、加减仓与风险预算 | 固定仓位、波动率目标、反马丁、受限马丁、止损止盈 |

### 同期评估 cohort

每个 `research_passed` 因子进入模拟观察时，创建一个不可变的 `EvaluationCohort`：

- [x] 锁定 `cohort_id`、候选因子版本、基准池版本、开始时间、结束条件与配置哈希。
- [x] 全部成员共享相同行情事件、交易日历、手续费、滑点、资金费率、成交和拒单模型。
- [x] 每个成员拥有独立现金、持仓、订单、成交、费用、权益、回撤与风险状态。
- [x] 行情缺失、延迟、交易所拒单和服务中断对所有可比较成员使用相同处理规则。
- [x] cohort 开始后不得事后新增容易战胜的基准；新增策略必须产生新的基准池版本和新 cohort。

## 三、P0：数据实时性与时间口径

### RT-01 数据新鲜度契约

- [x] 为行情统一增加 `event_time`、`bar_open_time`、`bar_close_time`、`fetched_at`、`received_at`、`is_closed`、`age_ms`、`source` 和 `quality_status`。
- [x] 区分 `historical_snapshot`、`closed_bar_live`、`forming_bar`、`ticker`、`best_bid_ask` 和 `trade`。
- [x] 页面和 API 不再仅以 `live` 命名判断实时性，必须返回实际新鲜度与是否已收盘。
- [x] 数据过期时明确降级或阻止评估，禁止静默使用旧缓存冒充实时数据。

### RT-02 OKX 公共实时行情

- [x] 增加 OKX 公共 WebSocket，订阅 ticker、最佳买卖价和需要的 K 线频道。
- [x] 因子计算只消费最新已收盘 K 线；形成中的 K 线只用于页面预览，不进入研究信号。
- [x] 模拟盘估值使用实时 ticker，中间价或预注册的可执行价格口径。
- [x] 下单模拟使用同一时刻最佳买卖价、点差、滑点和容量限制。
- [x] WebSocket 断线自动重连，并使用 REST 补偿；补偿过程写入数据质量证据。

### RT-03 A 股数据分层

- [x] A 股研究历史继续使用前复权已收盘 K 线。
- [x] 交易时段报价接入可用的实时或准实时报价接口，并记录接口实际延迟与授权边界。
- [x] AkShare、东方财富、腾讯等来源按字段和周期建立主备顺序，不把日线拉取标记为逐笔实时。
- [x] 非交易时段明确显示最后交易时间，避免把自然时间延迟误判为数据故障。

### P0 验收标准

- [x] 人工构造未收盘 K 线时，因子信号和仓位目标不发生变化；K 线收盘后只更新一次。
- [x] 实时 ticker 变化能够更新虚拟账本估值，但不能回写或重算已锁定研究结果。
- [ ] 断开 OKX 公共 WebSocket 后能自动重连并完成 REST 补偿，事件无重复、无缺口或缺口可解释。
- [x] 页面能够直接看到行情事件时间、获取时间、延迟、是否已收盘及过期状态。

## 四、P0：独立虚拟账本与公平执行

### LD-01 虚拟账本模型

- [x] 新增 `VirtualLedger`、`VirtualOrder`、`VirtualExecution`、`VirtualPosition`、`VirtualCashFlow` 和 `VirtualRiskEvent`。
- [x] 每个 cohort 成员独立初始化资金，禁止共享现金、仓位或已实现盈亏。
- [x] 账本支持现货和永续合约的合约乘数、保证金、资金费率、手续费和强平风险。
- [x] 使用事件幂等键，保证重试、刷新和服务恢复不会重复成交或重复扣费。
- [x] 任意时间点都能从订单、成交和现金流重建权益曲线。

### LD-02 统一执行模型

- [x] 所有策略使用相同的手续费档案、点差、滑点、容量、最小数量和价格步长。
- [x] 建立 `decision_time → tradable_time → quote_time → execution_time` 时间链，禁止同一根 K 线收盘价既生成信号又无延迟成交。
- [x] 对拒单、部分成交、缺少报价、价格跳空和流动性不足定义统一处理规则。
- [x] 把杠杆、最大敞口、最大单日损失和最大回撤作为 cohort 级公平上限。

### P0 验收标准

- [x] 两个相同策略使用不同账本时结果完全一致，且任何一方下单不会改变另一方余额或仓位。
- [x] 同一行情事件重复投递不会产生重复订单、成交、费用或权益变化。
- [x] 账本重放结果与在线累计结果逐事件一致。
- [x] 候选与基准的比较可以明确归因到信号、仓位、成本、滑点和市场暴露。

## 五、P1：同期策略基准池

### BM-01 基准策略注册表

- [x] 新增不可变 `BenchmarkStrategyDefinition`，保存策略类型、参数、适用市场、风险限制、代码版本和内容哈希。
- [x] 建立 `BenchmarkPoolVersion`，固定每个市场、周期和标的类别使用的基准集合。
- [x] 策略参数在 cohort 开始前预注册，禁止根据候选表现事后调整。
- [x] 记录基准策略不适用或无法成交的原因，不用缺失结果替代失败结果。

### BM-02 首批方向与朴素基准

- [x] 空仓基准：权益仅受必要账户费用影响。
- [x] 买入持有：固定初始建仓后持有。
- [x] 定投：按固定时间和固定金额买入。
- [x] 固定仓位：始终保持预注册的目标市场敞口。
- [x] 随机信号：使用不少于 20 个固定随机种子，形成偶然获利分布。

### BM-03 常见规则策略

- [x] 均线趋势：短长均线交叉或价格位于长期均线上方。
- [x] 时间序列动量：固定回看周期收益决定方向。
- [x] 通道突破：前高前低或 Donchian 通道突破。
- [x] 均值回归：布林带、滚动 z-score 或短期偏离回归。
- [x] 波动率目标：按实现波动率调整仓位，控制风险预算。

### BM-04 网格策略族

- [x] 固定区间等距网格。
- [x] 固定区间等比网格。
- [x] ATR 或实现波动率自适应网格。
- [x] 带趋势过滤的网格，在单边状态限制逆势加仓。
- [x] 网格统一记录库存风险、资金占用、成交次数、手续费占比、区间外突破损失和闲置资金。
- [x] 网格区间、层数、单格资金和退出规则全部预注册，禁止事后扩大区间掩盖失败。

### BM-05 资金管理压力基准

- [x] 固定仓位。
- [x] 波动率目标仓位。
- [x] 受限马丁：固定最大层数、总敞口、最大损失和停止条件。
- [x] 反马丁：盈利后在风险预算内增加仓位。
- [x] 固定止损止盈与时间退出。
- [x] 资金管理基准使用相同的底层信号进行配对实验，区分信号贡献和仓位贡献。

### P1 验收标准

- [x] 所有策略在同一行情、时间轴和执行模型下运行，但账本完全独立。
- [x] 候选因子必须同时与方向基准、规则策略、网格族和随机分布比较。
- [x] 当市场普涨导致大多数策略盈利时，报告标记为“市场顺风”，不能仅凭绝对收益通过。
- [x] 马丁或网格因高敞口盈利时，风险调整和等风险归一化比较能够揭示收益来源。

## 六、P1：因子质量评分与 AI 提示词升级

### AI-01 候选输入上下文

- [x] 向 AI 提供市场、周期、手续费、滑点、资金费率、最小交易量和风险预算。
- [x] 提供已尝试公式、等价族、相关性簇、失败原因、市场状态和剩余复杂度预算。
- [x] 提供种子候选的发现期指标，但继续屏蔽锁定确认集和前向模拟结果。
- [x] 明确禁止只修改相邻窗口、重复已有经济假设或通过增加复杂度包装相同公式。

### AI-02 结构化输出要求

- [x] 每个候选必须输出经济机制、预期方向、适用状态、失效状态和可证伪条件。
- [x] 输出预期换手、成本敏感度、数据延迟、参数平台和复杂度说明。
- [x] 输出与种子候选及现有因子的实质区别。
- [x] 输出建议对照基准，但由程序按版本固定的基准池决定实际运行集合。
- [x] 输出安全 DSL AST，继续禁止任意代码、未来数据和动态执行。

### AI-03 确定性候选评分

- [x] 发现阶段评分加入换手、交易次数不足、复杂度、相关性和参数敏感度惩罚。
- [x] 加入成本翻倍、成交延迟、容量收缩、数据扰动和市场状态稳定性。
- [x] 不使用单一总分直接决定胜者；保留 Pareto 维度和硬门禁。
- [x] 记录提示词版本、评分版本、候选生成器版本和完整输入输出哈希。

### AI-04 公平效果评估

- [ ] 固定候选预算，对比 AI、模板、随机 DSL、符号回归和人工候选。
- [ ] 统计合法率、非重复率、研究门禁通过率、相对基准超额率和单位计算成本。
- [ ] 至少完成多批次盲测后才能声明提示词或模型升级提升了因子质量。

### P1 验收标准

- [ ] AI 候选不再主要由相邻窗口变体构成，经济假设和算子族多样性达到预注册门槛。
- [ ] 提示词升级后，在相同预算下有效且非重复候选比例可复现提升。
- [x] LLM 不可用时，模板、随机 DSL、符号回归和统一评分仍能完整运行。

## 七、P2：同期比较、AI 评审与因子档案

- [x] 分解市场 Beta、因子信号、择时、仓位管理、成本、滑点和资金费率贡献。

- [x] 必须指出收益主要来源、候选弱于哪些基准、适用状态、失效状态和剩余风险。
- [x] AI 判断、模型、提示词、输入证据哈希和输出原文写入不可变审计记录。
- [x] AI 意见与程序门禁冲突时，以程序门禁为准，并展示冲突原因。

### EV-03 因子档案

- [x] 保存公式与版本、经济假设、失效条件、数据指纹、候选生成和提示词版本。
- [x] 保存研究门禁、确认集、同期基准池、所有虚拟账本和比较报告。
- [ ] 保存 AI 意见、程序门禁、人工审批、小额实盘配置和后续表现。
- [x] 事前假设与事后解释分栏保存，禁止覆盖原始假设。
- [x] 因子退役后保留完整历史，并记录替代关系和受影响策略。

### P2 验收标准

- [x] 任一“因子有效”结论都能回答：同期战胜了哪些基准、承担了多少额外风险、是否超过随机分布。
- [x] 任一 AI 建议都能恢复完全相同的输入证据和提示词版本。
- [x] 删除或隐藏失败策略不会改变原 cohort 的总体结论。

## 九、P3：小额实盘准入与持续降级

### LIVE-01 程序硬门禁

- [ ] 完成不少于预注册自然日和最小有效再平衡次数的同期模拟观察。
- [ ] 成本后收益为正，并对关键基准产生稳定的风险调整后超额收益。
- [ ] 候选表现超过随机策略分布的预注册分位数。
- [ ] 优势不能主要来自更高杠杆、敞口、换手、尾部风险或资金占用。
- [ ] 多个市场状态下没有不可接受的方向翻转或尾部失效。
- [ ] 数据新鲜度、成交率、容量、对账、Kill Switch 和风险限制全部通过。

### LIVE-02 AI 与人工审批

- [x] AI 只能创建“小额实盘申请草案”，不能提交交易开关或修改额度。
- [x] 人工审批页面展示全部失败证据、基准比较、随机分位数和剩余风险。
- [x] 审批必须锁定标的、周期、因子版本、策略版本、最大资金、最大敞口、最大损失和有效期。
- [x] 任意版本、参数或风险配置变化均重新申请，不沿用旧批准。
