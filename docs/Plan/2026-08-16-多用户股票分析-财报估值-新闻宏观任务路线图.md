# QuantHub 多用户股票分析、财报估值与新闻宏观任务路线图

> 创建日期：2026-08-16
>
> 本版只保留尚未完成的工作项。已完成的数据契约、后端模块、前端报告、测试、构建和验收记录已从路线图中移除；历史证据仍保留在对应的 `docs/Plan/evidence/` 目录和提交记录中。
>
> 产品边界：股票研究优先，A 股首发，美股随后接入；加密资产继续使用现有量价、新闻和因子研究，不套用上市公司财报模块。

## 一、剩余产品目标

底层数据、统一研究决策和基础报告能力已经具备。后续重点是：

- 按用户用途裁剪工作台，让不同用户默认只看到与任务相关的能力。
- 将工作台画像和个性化导航从浏览器本地设置提升为账户级配置。
- 继续补齐财报、估值、宏观和事件分析的深度规则。
- 让 AI 分析报告按章节流式生成，并能中断、恢复和复现。

## 二、工作台画像与用户分层

工作台画像与报告内部研究模式是两个维度：前者决定用户进入系统后看到哪些工作区和首页模块，后者只决定单份股票报告的信息密度与术语。

### PROFILE-01 画像定义

| 画像 | 默认目标 | 默认工作区 |
| --- | --- | --- |
| 股票投资 | 自选、研究、持仓复核和提醒 | 总览、市场研究、账户风控、设置 |
| 主动交易 | 研究、信号审核、模拟/实盘交易和风险控制 | 总览、市场研究、交易、账户风控 |
| 量化研究 | 因子、策略、回测、组合和实验复现 | 总览、市场研究、策略、模拟交易 |
| 运营管理 | 成员、权限、数据源、自动化和故障处理 | 总览、设置、账户风控 |
| 自定义 | 用户自行组合工作区与入口 | 按用户配置 |

- [ ] 用“股票投资 / 主动交易 / 量化研究 / 运营管理 / 自定义”替换全站“精简 / 完整”界面选择。
- [ ] 首次进入时让用户选择主要用途，并为每种画像提供可理解的默认工作区说明。
- [ ] 画像只改变默认呈现和导航，不改变底层数据、计算结果、风险门禁和统一 `ResearchDecision`。
- [ ] 允许用户随时切换画像；切换不删除历史研究、策略、订单或提醒。

### PROFILE-02 账户级配置

- [ ] 将工作台画像保存到当前用户账户，不能只写入 `localStorage`。
- [ ] 将隐藏工作区、隐藏模块、固定入口、默认首页、默认市场和最近入口统一保存到用户配置。
- [ ] 配置接口按当前用户隔离，支持读取、更新、版本号和审计记录。
- [ ] 浏览器更换、设备更换或清空本地存储后，用户仍能恢复自己的工作台配置。
- [ ] 用户画像配置与研究偏好配置分开建模，避免把导航用途和股票报告模式混成一个字段。

### PROFILE-03 权限与入口裁剪

- [ ] 前端根据后端返回的权限集合彻底移除无权访问的工作区、菜单项、命令面板命令和首页卡片。
- [ ] 无权路由不能仅靠隐藏导航保护；直接访问深链接时必须返回统一的无权限页面或重定向到可见首页。
- [ ] 权限过滤与画像过滤分开执行：最终可见能力为“用户权限 ∩ 画像默认能力 ∩ 用户自定义设置”。
- [ ] 画像不能突破后端权限；管理员、操作员、审核员和只读成员的权限边界继续由服务端强制执行。
- [ ] 当用户权限被回收时，已打开的页面、命令面板和异步请求都要及时进入无权限状态。

### PROFILE-04 首页与导航

- [ ] 首页根据工作台画像切换内容，不让股票投资用户默认看到自动化、运行故障、策略运营或成员治理内容。
- [ ] 股票投资首页优先展示自选、研究结论、证据新鲜度、下一事件和提醒。
- [ ] 主动交易首页优先展示信号队列、持仓风险、交易状态和待复核动作。
- [ ] 量化研究首页优先展示因子实验、策略版本、回测状态和研究任务。
- [ ] 运营管理首页优先展示成员权限、系统状态、自动化作业、数据源和故障。
- [ ] 自定义画像支持拖拽或排序固定入口，但不允许固定无权访问的入口。

## 三、股票报告研究模式

报告内部继续保留四种研究模式，不与全站工作台画像合并：

| 报告模式 | 适用场景 | 主要差异 |
| --- | --- | --- |
| 简明 | 快速判断 | 结论、依据、风险、观察动作 |
| 投资研究 | 主动研究与持仓复核 | 财报趋势、估值、事件和条件 |
| 专业验证 | 来源与模型复核 | 原始证据、口径、版本和计算 |
| 量化实验 | 因子与策略研究 | 因子、股票池、策略和实验数据 |

- [ ] 明确前端状态和后端契约中“工作台画像”与 `ResearchMode` 的独立字段、独立保存和独立切换行为。
- [ ] 四种报告模式读取同一研究运行和同一 `ResearchDecision`，不得因为模式不同重新计算或改变建议状态。
- [ ] 深链接同时保存工作台上下文和报告模式，但研究结果 ID 保持一致。
- [ ] 模式切换不得隐藏证据不足、方向冲突、数据过期、风险警告或执行门禁。

## 四、财报、估值、宏观与事件剩余工作

### DATA-01 财务报表数据管线

- [ ] A 股扩展业绩预告、业绩快报和分红送转结构化提供方。
- [ ] 美股扩展 8-K 和公司指引结构化提供方。
- [ ] 扩展后台增量抓取缓存和独立计划任务。

### DATA-02 估值与可比公司数据

- [ ] 扩展停牌、复权、拆股、增发和跨币种换算的完整公司行为处理。

### DATA-04 全球宏观事件与经济日历

- [ ] 扩展汇率、国债收益率和流动性指标提供方。
- [ ] 支持地缘政治、制裁、贸易政策和大宗商品冲击，并明确来源等级与不确定性。

### DATA-05 标的关系与事件传导图

- [ ] 扩展逐公司行业、商品、供应链、收入区域和监管暴露事实关系。

### ANL-01 财务质量与盈利趋势

- [ ] 区分增长质量：价格、销量、并表、一次性项目、会计口径和汇率影响。
- [ ] 计算盈利能力、营运效率、偿债能力、资本开支、股东回报和稀释风险。
- [ ] 扩展应收存货异常和非经常性损益规则。
- [ ] 行业差异采用行业模板，不使用一套阈值评价银行、制造、软件和周期行业。

### ANL-02 估值状态与敏感度

- [ ] 建立盈利、利润率、贴现率和终值假设敏感度。
- [ ] 区分“低估但基本面恶化”“高估但盈利上修”“周期底部失真”等情形。
- [ ] 补充可交互关键假设与敏感度场景。

### ANL-03 公司事件影响分析

- [ ] 同一事件对公司、行业和竞争对手分别判断，不复用单一情绪分数。
- [ ] 计算事件新颖度、来源可信度、多源一致性和是否已被价格反映。

## 五、产品体验剩余工作

- [ ] 最近研究复用必须同时校验数据版本、新鲜度、用户目的和研究周期。
- [ ] K 线叠加财报公告、重大公司事件和宏观事件标记。
- [ ] 用户可订阅“只通知重要变化”，避免新闻噪声。
- [ ] 标记上次观察条件是否触发，以及触发后价格和基本面如何演化。

## 六、AI 使用边界与解释质量

- [ ] LLM 只处理非结构化材料、跨证据归纳和自然语言解释。
- [ ] 财务指标、估值分位、经济数据意外值和 K 线指标使用确定性计算。
- [ ] 模型输入只包含已保存、带来源的证据摘要，并附证据 ID。
- [ ] 模型输出采用固定 schema，引用不存在的数字或事件时整项拒绝。
- [ ] 重要结论必须至少有一个直接来源；宏观传导结论必须同时有事件和标的暴露证据。
- [ ] AI 不能覆盖程序生成的证据不足、冲突或执行门禁状态。
- [ ] 支持一次受约束修复重试，仍失败则降级为结构化规则结果。
- [ ] 简明模式优先回答“发生什么、为什么重要、接下来观察什么”。
- [ ] 专业模式区分事实、计算结果、模型推断和不确定性。
- [ ] 禁止使用“必涨、稳赚、确定性机会”等承诺性表达。
- [ ] 对预测性内容提供时间范围、反例和失效条件。

## 七、AI 分析报告流式输出

流式只改变报告生成和展示方式，不改变点时证据、确定性指标、`ResearchDecision`、风险门禁或最终建议状态。

### STREAM-01 报告流协议

- [ ] 在现有分析任务状态 SSE 之外，增加面向报告内容的版本化事件协议，至少支持 `report_started`、`section_started`、`delta`、`section_completed`、`report_completed`、`report_error` 和 `heartbeat`。
- [ ] 每个事件包含 `task_id`、`research_run_id`、`report_id`、`sequence`、`event_version` 和服务端时间；`sequence` 单调递增且可用于断点续传。
- [ ] 流式正文只允许来自已保存并带证据 ID 的输入摘要；不得在前端拼接未经校验的模型字段。
- [ ] 结构化结论、证据覆盖、方向冲突、执行资格和建议枚举由程序先生成，AI 只能解释，不得覆盖这些字段。
- [ ] 报告最终快照保存完整正文、章节状态、引用证据 ID、模型版本、提示版本、数据截止时间和内容哈希。

### STREAM-02 后端与模型编排

- [ ] LLM 适配层支持 provider-neutral streaming，并统一转换为内部事件；不把某一家供应商的 chunk 格式暴露给前端。
- [ ] 分析任务完成确定性模块后立即启动报告流，不必等待所有非关键扩展模块；缺失模块必须在报告中标记为缺口。
- [ ] 支持按章节生成和持久化，单个章节失败时保留已完成章节，并降级为结构化规则解释或可重试状态。
- [ ] 支持客户端断线重连、`Last-Event-ID` / `after_sequence` 续传、心跳、超时、取消和重复事件去重。
- [ ] 流式报告必须继续遵守用户隔离；用户只能读取自己拥有的 `task_id`、`research_run_id` 和 `report_id`。
- [ ] 报告生成失败、证据不足或方向冲突时，流中明确发送阻断原因，不能先输出确定性买卖措辞再在末尾修正。

### STREAM-03 前端交互

- [ ] 研究页以章节卡片显示生成状态：等待、生成中、已完成、部分失败和已跳过，并显示当前数据截止时间。
- [ ] 文本增量渲染不能导致页面跳动；用户可以暂停自动滚动、复制已生成内容，并在完成后查看完整引用。
- [ ] 刷新或返回研究页时根据 `report_id + sequence` 恢复内容；断线时显示“正在恢复”，而不是把报告清空。
- [ ] 流式阶段固定展示“研究参考，不是收益承诺”、证据不足、数据过期和方向冲突警告。
- [ ] 简明、投资研究、专业验证和量化实验模式使用同一报告快照与同一结论，只改变默认章节、摘要长度和术语级别。
- [ ] 提供“停止生成”和“重新生成本章节”操作；重新生成必须产生新的报告版本，不覆盖旧报告。

### STREAM-04 数据模型与 API

- [ ] 新增不可变 `ResearchReport` / `ResearchReportSection` / `ResearchReportEvent` 契约，报告版本与研究证据版本绑定。
- [ ] 新增报告查询、事件流、断点续传、取消章节和重新生成章节接口；接口返回稳定枚举、来源、版本和新鲜度。
- [ ] 导出报告默认使用已完成的最终快照，并同时保留流式事件摘要，不能导出半成品正文冒充最终报告。
- [ ] 报告事件保留策略、过期策略和权限审计明确；事件流不得写入 API key、原始提示词中的敏感凭据或其他用户内容。

### STREAM-05 验收与发布门禁

- [ ] 首字节、首个结构化章节和完整报告分别有可观测耗时指标；SSE 断线重连后无重复、无乱序、无丢失章节。
- [ ] 在 390x844、768x1024、1280x720 和 1440x900 四档视口验收流式渲染、暂停滚动、重连和错误状态。
- [ ] 覆盖正常完成、模型超时、模型拒绝、单章节失败、证据缺失、任务取消、刷新恢复和重复点击等测试场景。
- [ ] 验证同一 `ResearchDecision` 在四种用户模式下方向、置信度、覆盖状态、建议状态和失效条件完全一致。
- [ ] 只有 `report_completed` 且最终快照校验通过后，报告才允许进入历史复盘、导出、提醒或任何执行相关流程。

## 八、质量与发布门禁剩余工作

- [ ] 至少两个独立来源交叉验证关键财务和宏观字段，或明确单一来源状态。
- [ ] 美股接入阶段至少覆盖正常财年、非自然年财年和亏损公司。
- [ ] FOMC、CPI 和一个地缘事件完成历史点时回放。

## 九、实施里程碑

| 里程碑 | 工作重点 | 完成定义 |
| --- | --- | --- |
| P1 工作台画像 | 画像、账户级配置、权限过滤、首页裁剪 | 五类画像可切换，配置跨设备保持，越权入口不可见且不可访问 |
| P2 研究模式收口 | 工作台画像与四种报告模式解耦 | 同一研究运行在不同模式下结论一致、信息密度不同 |
| P3 数据与分析扩展 | 财报、估值、宏观、事件剩余规则 | 新增数据可点时追溯，分析结果有行业模板和失效条件 |
| P4 AI 流式报告 | 事件协议、章节生成、断点续传、最终快照 | 报告可增量显示、刷新恢复、失败降级并可复现 |
| P5 发布门禁 | 真实数据、流式体验、权限和四视口验收 | 全部剩余待办通过，且无未来数据泄漏和越权访问 |

## 十、路线图完成定义

只有同时满足以下条件，才能把本路线图标记为完成：

- [ ] 五类工作台画像可用，且画像、隐藏模块和固定入口保存在用户账户。
- [ ] 前端只展示用户有权限且被画像/个人设置启用的入口；直接访问无权路由也会被阻断。
- [ ] 首页按画像提供不同工作内容，股票投资用户默认不看到运营、故障和策略管理内容。
- [ ] 工作台画像与简明、投资研究、专业验证、量化实验四种报告模式完全解耦。
- [ ] 剩余财报、估值、宏观和事件分析能力具备点时来源、行业规则和失效条件。
- [ ] AI 分析报告支持章节级流式输出、断点续传、取消、单章节重试和最终快照。
- [ ] 流式半成品不得进入执行、提醒、导出或历史复盘流程。
- [ ] 四种报告模式复用同一 `ResearchDecision`，方向、置信度、证据覆盖、建议状态和风险门禁一致。
- [ ] 真实数据、权限、流式重连、移动端和四档视口验收全部通过。
