# QuantHub 因子研究基线与剩余缺口

> 基线日期：2026-08-01
> 适用范围：QuantHub Web 工作台中的因子研究能力
> 本文合并原“因子研究与交易可用性路线图”“AI 因子发现与交易验证路线图”和 AI 治理补充说明。工作台收口进度记录在 [Web 工作台收口路线图](../../Plan/2026-08-09-Web工作台收口与OKX实盘路线图.md)。

## 1. 状态定义

- `draft`：已登记定义，尚未进入正式研究。
- `exploratory`：仅在发现集或探索阶段表现可关注。
- `research_passed`：通过锁定样本外统计门禁，不代表可交易。
- `trading_validated`：额外通过目标市场成本、容量、执行约束、组合增量和完整模拟周期。
- `degraded`：漂移或交易门禁失效，停止新增部署但保留历史证据。
- `retired`：明确退役，定义和审计记录不可删除。

当前不存在“实盘可用”研究状态。真实账户执行继续关闭。

## 2. 已形成的研究能力

### 2.1 统计准确性

- Yahoo 美股行情使用 `adjclose` 并同步调整 OHLC。
- 显著性考虑重叠收益有效样本量，支持 HAC/Newey-West。
- 同批因子执行 Benjamini-Hochberg 校正。
- 样本外验证支持扩展和滚动窗口、purge、embargo、窗口稳定性和方向翻转检查。
- 研究记录保存引擎、公式、参数、门槛、数据快照和哈希。

### 2.2 横截面、成本与组合

- 支持 Rank IC、ICIR、分层收益、多空收益、覆盖率、换手、容量和拥挤度。
- 成本模型可以表达 A 股、美股、加密和 MT5 的费用与执行约束。
- 支持成本敏感度、盈亏平衡成本、成交参与率和容量限制。
- 因子相关性、正交化和组合增量价值进入研究门禁。
- 研究到策略实验传递不可变定义、研究运行、数据快照、权重、周期和成本配置。

### 2.3 AI 与试验治理

- 不可变因子注册表保存 DSL AST、参数、方向、版本、经济逻辑和哈希。
- DSL 使用白名单算子并检查未来信息、单位、形状、复杂度和重复公式。
- 候选收件箱区分人工、AI、模板、随机 DSL 和符号回归来源。
- 全局实验账本累计记录成功和失败试验，锁定确认集开启不可逆。
- AI 只能提交结构化假设、候选公式和证伪建议。
- AI 不能读取锁定确认集标签，不能运行任意 Python，不能修改统计状态或产生订单。
- 非线性模型必须在嵌套时间序列中稳定优于线性基准，才可进入模拟验证。

### 2.4 模拟与持续监控

- 模拟订单保存因子、研究运行、再平衡周期、信号时间、可成交时间、理论价和容量占用。
- 模拟成交保存成交价、方向一致滑点、拒单原因和账本同步状态。
- 漂移监控覆盖 IC 衰减、方向翻转、覆盖率、PSI、分布距离、相关结构、成本和容量。
- 门禁失败会追加 `degraded` 事件并定位受影响策略；重复调度保持幂等。
- 因子状态变化、数据过期、IC 衰减和回撤越界支持复验与提醒。

## 3. 当前证据快照

- `demo_artifacts/a_share_300_factor_baseline.json`：300 个真实 A 股标的、516 个共同 ordinal session、14 个因子。
- `demo_artifacts/a_share_preregistered_experiments_01_07.json`：实验 1、2、3、4、5、7，共 6 个；1 个通过、5 个失败。
- 最新已记录的 `600519` 运行在没有可用因子时返回 `usable_factors=0`、`multifactor_constructed=false`。
- 数据、公式、实验、模型、提示词、成本和结果分别保存版本与哈希。

这些结果只证明当前数据和口径下的研究过程可审计，不证明未来收益或实盘可用。

## 4. 证据限制与冲突解释

早期路线图曾把“历史股票池、时点中性化和四市场验证”标为完成；v0.3.0 真实证据复核确认，以下关键数据仍不完整：

- 当前真实基线使用 ordinal session，不是真实自然日期。
- 历史退市、ST、停牌和指数成分变化缺少完整时点证据。
- 行业、市值、Beta 和基本面暴露仍可能是当前静态值，不能回填历史。
- 公告和新闻缺少足量人工标注验证集。

因此，历史路线图的“完成”只表示代码路径或受控样例已实现；涉及真实时点数据的研究结论以本节限制为准。

## 5. 剩余研究任务

- [ ] 股票池按日期保存成分，纳入退市、暂停上市、ST、停牌、上市不足期和历史指数调入调出。
- [ ] 市值、行业、Beta 和基本面暴露使用对应日期可获得的数据，禁止当前静态值回填历史。
- [ ] 在固定候选预算下，证明 AI 相对随机 DSL 的有效且非重复候选比例有可复现提升。
- [ ] 在人工标注样本上，让事件类型、实体和时间准确率达到预注册门槛。
- [ ] 完成 Amihud 非流动性、成交额分位和换手突变实验，并验证小市值暴露中性化后的结果。
- [ ] 完成公告事件与价格状态交互实验，例如业绩上修叠加中期趋势或超跌状态。
- [ ] 增加因子相关性簇、参数平台、年度稳定性、市场状态和增量价值视图。
- [ ] 完成 AI、人工模板、随机 DSL 和符号回归的固定预算公平对照。
- [ ] 至少一个因子完整走过 `draft` 到 `trading_validated`，并能恢复全部证据。
- [ ] 所有通过状态展示原始证据、门禁规则、目标市场和剩余风险。

## 6. 工作台与执行边界

- [ ] 因子注册表、实验账本、数据快照、统计结果和策略发布包使用可审计的数据模型。
- [ ] A 股、美股、OKX 和 MT5 使用独立标的池、日历、标签、成本和研究门槛。
- [ ] 跨市场结果只作为稳健性证据，不继承状态。
- [ ] 策略发布包固定公式、数据、成本、容量、风险、模拟结果和审批记录。
- [ ] Web 工作台的研究域不保存真实交易密钥，也不直接创建真实订单。
- [ ] 只有不可变策略发布包可以交付给 OKX Runner。

## 7. 发布门禁

- [ ] 数据、公式、实验、模型、提示词、成本和结果具有版本与哈希。
- [ ] 研究运行可以从锁定快照完整复现。
- [ ] 统计通过与交易验证在数据模型、API 和界面中明确分离。
- [ ] AI 无法修改程序统计结论、研究预算和交易状态。
- [ ] 目标市场成本、容量、执行和组合增量门禁全部通过后，才能标记 `trading_validated`。
- [ ] 真实执行继续由 OKX Runner 独立评审，不在研究域内开启。
