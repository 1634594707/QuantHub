# QuantHub 新手易用性与研究结果闭环需求

> 文档日期：2026-07-30
> 文档性质：产品需求基线，不重复维护开发完成状态
> 专项进度记录：`BEGINNER_USABILITY_ROADMAP.md`（历史实施记录）
> 功能归属真值源：`../../FUNCTION_BOUNDARIES.md`

## 1. 背景

用户反馈 QuantHub 功能完整，但第一次使用时存在明显学习门槛：不知道从哪里开始、不理解专业参数、不确定结果在哪里查看，也不清楚完成分析后下一步应该做什么。

本需求的目标不是删除专业能力，而是建立两层体验：

- 新手层：用最少选择完成一次可信的股票评估并看懂结果。
- 专业层：保留因子验证、策略实验、信号审核、账本和运营控制等完整能力。

所有改造必须遵守现有功能边界，不新增与综合评估、因子验证、研究任务或自动化中心职责重复的页面。

## 2. 当前结果在哪里查看

| 结果类型 | 当前查看位置 | 是否持久化 | 说明 |
| --- | --- | --- | --- |
| 股票综合评估 | `研究 -> 综合评估`，或 `/research/{symbol}` 的历史视图 | 是 | 可查看研究记录、证据、对比和导出 |
| 因子统计验证 | `研究 -> 因子验证`，即 `/factor-research` | 是 | 自动保存 IC、衰减、样本外收益、回撤、方法对比和参数快照，可在历史记录中恢复 |
| AI 科研复核 | `/factor-research` 页面底部 `05 / AI RESEARCH REVIEW` | 是 | 必须先运行因子研究，再点击“启动 AI 复核”；结果追加到同一研究记录并可随统计结果恢复 |
| 异步研究任务状态 | `研究 -> 研究任务`，即 `/tasks` | 是 | 只负责查看进度、失败、取消和重试，不承载研究结果正文 |
| 自动化运行记录 | `运营 -> 作业调度`，即 `/automation` | 是 | 只展示定时作业及其运行状态，不是研究结果中心 |

因子统计与 AI 复核的保存、回看闭环已经完成；下一阶段继续补齐新手结果摘要、两次记录比较，以及研究任务和自动化运行到结果正文的直接跳转。

## 3. 目标用户

### 3.1 小白用户

- 知道股票名称或代码，但不了解 IC、ICIR、CVaR、Calmar 等术语。
- 希望快速回答“现在怎么看、依据是什么、风险是什么、下一步做什么”。
- 容易把回测收益、AI 置信度或单一指标误解为确定性交易建议。
- 需要默认值、中文解释、明确的进度和可恢复的结果。

### 3.2 进阶用户

- 能理解周期、成本、样本外检验和回撤。
- 需要展开查看统计证据、数据来源、方法口径和 AI 审阅细节。
- 需要保存、复跑、对比和导出研究结果。

### 3.3 专业用户

- 需要完整研究、策略、执行和运营工作区。
- 需要参数控制、版本追踪、审计信息和原始结构化数据。
- 不应因新手模式而失去已有专业能力。

## 4. 产品目标与成功标准

1. 新用户在 5 分钟内完成第一次股票评估。
2. 从进入系统到开始评估，主要操作不超过 3 次点击。
3. 新手首次使用不需要理解市场代码、K 线周期代码或内部运行 ID。
4. 每个结果首先回答结论、依据、风险、失效条件和下一步操作。
5. 用户刷新页面后仍能恢复最近一次已完成结果。
6. 用户能从任务、告警或自动化运行记录直接跳转到对应结果，而不是重新寻找入口。
7. 数据源或 AI 失败时，保留已经完成的统计结果，并提供可执行的处理方式。
8. 新手默认只接触研究和模拟能力，不出现直接实盘下单引导。

## 5. 设计原则

### 5.1 一条主路径

新手默认路径固定为：

```text
选择股票 -> 选择研究目标 -> 运行评估 -> 阅读摘要 -> 保存或设置提醒
```

不得要求新手在新闻、价格行为、模型共识、因子和策略页面之间手工拼接结论。

### 5.2 渐进式展示

- 第一层只显示中文结论、核心依据和风险。
- 第二层显示数据来源、更新时间和分维度证据。
- 第三层“专业详情”显示 IC、ICIR、p 值、衰减、CVaR、模型元数据和输入指纹。
- 专业指标不能删除，但不应阻挡新手完成主任务。

### 5.3 结论与证据分离

- 确定性统计结论由程序计算。
- AI 只解释证据、检查风险和提出后续实验。
- AI 不得修改“可用 / 观察 / 淘汰”等程序状态。
- 回测、AI 和历史数据均不得包装成收益承诺。

### 5.4 结果有归属

- 综合评估结果归属“综合评估”。
- 因子研究结果归属“因子验证”。
- 研究任务只显示运行状态并链接结果。
- 自动化中心只管理调度和运行历史并链接结果。
- 不新增独立的“AI 结果中心”或第二套研究列表。

## 6. 核心需求

### P0-01 首次进入与模式选择

- 首次进入提供“新手模式”和“专业模式”的清晰选择。
- 新手模式默认展示：驾驶舱、股票评估、自选、模拟、设置。
- 专业模式继续展示研究、策略、执行和运营工作区。
- 模式切换可随时执行，并在刷新后保持。

验收标准：小白用户无需阅读说明即可找到“评估一只股票”。

### P0-02 研究目标向导

用户选择股票后，只需选择自然语言目标：

- 看当前状态：进入综合评估。
- 验证一种量化方法：进入因子验证，并使用推荐参数。
- 测试一个策略：进入策略实验。

验收标准：新手不需要先理解各工作区名称才能选择正确入口。

### P0-03 参数默认值与高级选项

- 默认提供短线、波段、中线三种研究周期。
- 市场、周期、历史长度、预测窗口和成本使用稳健默认值。
- 原始参数放入“高级选项”，修改后显示影响说明。
- 对样本过少、成本为零或周期不匹配进行提交前提示。

验收标准：使用默认值即可完成一次有效研究，不出现空白或无意义结果。

### P0-04 新手结果摘要

所有研究结果首屏统一展示：

1. 当前结论。
2. 最多三条主要依据。
3. 最多三条主要风险。
4. 结论失效条件。
5. 数据时间和适用周期。
6. 下一步建议操作。

专业指标放在摘要之后，不能先于用户最关心的问题。

### P0-05 因子研究结果持久化

每次成功的因子验证应生成稳定的研究记录，至少保存：

- 记录 ID、标的、市场、周期和创建时间。
- 历史长度、预测窗口、交易成本和数据来源。
- 数据质量、训练/隔离/样本外区间。
- 因子状态、权重、IC、ICIR、衰减和命中率。
- 方法对比、收益、回撤和风险指标。
- 当前回撤信号和方法口径版本。
- AI 复核正文、模型、Token、输出次数和输入指纹。
- AI 是否通过结构校验、统计结论是否保持锁定。

安全要求：不得保存 API Key、访问令牌或完整模型密钥配置。

验收标准：刷新、关闭浏览器或重启服务后，可以恢复同一份结果。

### P0-06 因子验证历史与回看

- 在 `/factor-research` 内增加“当前研究 / 历史记录”视图，不新增一级页面。
- 历史记录支持按标的、市场、周期、日期和结果状态筛选。
- 可重新打开、复制参数、重新运行、重新 AI 复核和导出。
- 旧记录必须显示当时的数据时间、算法版本和模型版本。
- 两次记录可比较因子状态变化、IC 变化、回撤变化和方法排名变化。

验收标准：用户可以回答“这次结果和上次相比发生了什么”。

### P0-07 跨页面结果跳转

- 研究任务完成后提供“查看结果”。
- 自动化运行成功后提供“查看本次产出”。
- 故障恢复后返回原研究记录。
- 提醒和信号显示关联研究记录。
- 跳转使用稳定的记录 ID，不依赖当前页面内存状态。

验收标准：用户不需要从任务 ID 猜测结果位于哪个模块。

### P0-08 失败与部分成功

- AI 超时时保留因子统计结果。
- 数据源失败时说明失败来源，并提供重试或切换数据源动作。
- 错误信息使用中文，不直接显示 SDK 堆栈或底层异常类名。
- 重试只重跑失败步骤，避免重复计算和重复 AI 计费。
- 页面明确区分“统计完成、AI 失败”和“整个研究失败”。

验收标准：任一可选 AI 模块失败，不会让用户误以为统计研究也丢失。

### P0-09 下一步操作

研究完成后根据结果提供有限且明确的动作：

- 保存研究。
- 与上次比较。
- 设置价格或风险提醒。
- 将通过验证的候选方案送入策略实验。
- 进入模拟交易前查看风险说明。

因子验证页面不得直接创建实盘订单。

### P1-01 术语解释

- 为 IC、ICIR、p 值、样本外、最大回撤、CVaR、Sharpe、Sortino 和 Calmar 提供简短中文解释。
- 解释应回答“高低意味着什么”和“不能说明什么”。
- 使用悬浮提示或详情抽屉，不在主页面堆放教学文字。
- 第一次出现专业术语时提供一次性引导，可永久关闭。

### P1-02 示例报告

- 提供只读示例报告，覆盖正常、风险退出、数据不足和 AI 失败四种情况。
- 示例数据必须明确标记，不得混入用户研究记录。
- 示例报告应允许展开专业详情，帮助用户建立阅读顺序。

### P1-03 研究模板

- 提供“稳健验证”“趋势研究”“回撤检查”等模板。
- 模板只设置参数和研究重点，不改变算法结论规则。
- 用户可查看模板采用的周期、成本和样本要求。

### P2-01 学习与反馈

- 收集新用户首次任务完成率、完成时间、放弃位置和错误类型。
- 允许用户对结果可读性进行简单反馈。
- 不采集 API Key、持仓明细或模型原始密钥。
- 根据真实任务失败点优化向导，不以页面访问量代替成功率。

### 新手模式


### 专业模式

## 8. 第一阶段实施范围

建议第一阶段只完成以下闭环：

1. 保存因子统计和 AI 复核结果。
2. 在因子验证页增加历史记录与恢复。
3. 从研究任务和自动化运行跳转到对应结果。
4. 增加新手结果摘要和专业详情折叠。
5. 把底层错误改为中文原因和处理动作。
6. 为关键术语增加按需解释。

以下内容不进入第一阶段：

- 新增第二套 AI 分析页面。
- 自动生成实盘订单。
- 用 AI 替代样本外统计检验。
- 在自动化中心复制完整研究报告。
- 同时重构所有专业工作区。

## 9. 验收场景

### 场景 A：第一次评估股票

用户输入“贵州茅台”，选择“看当前状态”，使用默认参数完成评估；在 5 分钟内能说出结论、两条依据、一条风险和适用周期。

### 场景 B：完成因子验证

用户运行 600519 因子验证，看到统计结论后启动 AI 复核；刷新页面后仍能从历史记录恢复统计结果和 AI 结果。

### 场景 C：AI 超时

统计研究完成但 AI 超时；页面保留全部统计结果，显示“统计完成、AI 未完成”，用户可只重试 AI，不重新拉取和计算行情。

### 场景 D：从自动化查看产出

定时因子任务执行成功；用户在自动化运行记录点击“查看产出”，直接进入对应因子研究记录，而不是停留在运行日志。

### 场景 E：比较历史变化

用户选择同一标的的两次研究记录，能看到因子状态、样本外 IC、最大回撤和方法排名的变化，并知道两次使用的数据时间与算法版本。

## 10. 非功能要求

- 桌面端与 390px 移动端均不得产生页面级横向滚动。
- 关键操作可使用键盘完成，并具有清晰焦点状态。
- 结果恢复不能依赖浏览器内存或单个 React 组件状态。
- 所有研究记录必须带数据来源、快照时间和算法版本。
- AI 调用必须记录模型与输入指纹，但不得记录密钥。
- 默认保持 `live_trading=false`。
- 新增结果存储前必须定义数据库迁移、回滚和兼容策略。
