# 真实券商与交易所适配评估

评估结论：当前产品执行通道只评估独立 OKX Runner，不接入新的券商或交易所适配器，
`live_trading` 继续保持 `false`。Runner 已具备订单状态机、恢复、风险模式和对账代码，
但完整外部 Demo 观察、差异闭环与独立 live 审批仍未形成可验收结论。

## 当前源码边界

- 浏览器只访问统一 API 的 `/trading/*`，API 通过服务端地址和令牌访问
  `apps/okx_runner`；浏览器不读取 OKX 凭据或 Runner 令牌。
- Runner 支持稳定客户端订单号、订单状态持久化、未完成订单恢复、撤单、风险模式、
  账户/持仓读取和订单/成交/余额/持仓对账。
- `shadow` 环境只读；`demo` 需要显式启动并配置本地凭据；`live` 还要求
  `QH_RUNNER_LIVE_APPROVED=1`。
- 旧 `apps/dispatcher/router.py` 路径保留为遗留 dry-run/策略基础设施，不是 Web 产品的
  OKX 执行入口。
- A 股、MT5 和 Solana 没有当前可验收的真实报单通道。
- `apps/api/domains/strategies/service.py` 的实时接口明确返回 `mode="paper"`。
- 当前缺口主要是外部 OKX Demo 的连续观察、私有通道稳定性、差异清零证据、轮值与
  独立审批，不是再创建第二套执行适配器。

## 接入前必须补齐

- 在 OKX Demo 完成连续观察，覆盖提交、撤单、部分成交、费用、重启恢复和定时对账。
- 证明超时与未知订单先查询外部状态，不发生盲目重复提交。
- 对最小下单量、价格精度、杠杆、费用币种和交易时段形成真实账户证据。
- 将所有未解决对账差异归零，并验证进程重启后的恢复顺序。
- 密钥只能来自部署密钥管理，不进入 API 响应、日志、审计前后值或前端存储。
- 验证 `cancel_only`、`halted` 和恢复到 normal 的人工授权流程。
- 完成断网、限流、拒单、时钟偏差、凭据异常和私有通道断线演练。

## 后续评审入口

满足以上条件后，只评审现有 OKX Runner 的小额 live 试点，不同时接入多个市场。
评审材料必须包含状态机、幂等策略、对账报告、故障演练结果、权限矩阵、观察记录和
回滚步骤；材料齐全前不修改 `live_trading=false` 的默认值。
