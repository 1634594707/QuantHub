# 真实券商与交易所适配评估

评估结论：当前版本不接入新的真实券商或交易所适配器，`live_trading` 继续保持 `false`。现有模拟执行、权限、统一审计、持久化任务和恢复演练已经形成基础闭环，但真实订单状态与外部账户对账仍未形成可验收闭环。

## 当前源码边界

- `apps/dispatcher/router.py` 的 `OrderRouter.route()` 在 `dry_run` 下只输出订单意图。
- 加密来源 `okx_grid` 通过 `OkxSource(...)._exchange` 直接调用 `create_market_order()` 或 `create_limit_order()`。
- `OrderRouter._route_okx()` 捕获异常后只写日志，返回值没有外部订单编号、拒单原因或成交状态。
- `OrderRouter._route_solana()` 只记录委托日志，没有提交结果。
- 非加密市场进入 `_route_a_shares()`，只记录条件单；没有 A 股或 MT5 真实报单通道。
- `apps/api/domains/strategies/service.py` 的实时接口明确返回 `mode="paper"`。
- 真实风控已从账本 NAV、总敞口、标的持仓和策略分配计算订单金额，但这些结果尚未与外部账户余额、冻结资金和未完成订单对账。

## 接入前必须补齐

- 定义独立适配器协议，返回外部订单编号、接收时间、状态、已成交数量、均价、费用和原始错误码。
- 使用稳定的客户端订单编号实现提交幂等，重试不能生成重复订单。
- 持久化 `submitted`、`accepted`、`partially_filled`、`filled`、`cancelled`、`rejected` 和 `unknown` 状态及每次转换。
- 建立启动对账和定时对账，把外部订单、成交、余额、持仓与本地账本差异写入故障中心。
- 对超时结果使用 `unknown`，必须先查询外部状态，禁止直接重复报单。
- 为撤单、部分成交、费用币种、最小下单量、价格精度和交易时段建立适配器测试。
- 密钥只能来自部署密钥管理，不进入 API 响应、日志、审计前后值或前端存储。
- 增加全局停机开关、单账户停机开关和只撤单模式，并由 `config.manage` 控制。
- 在交易所或券商沙箱完成断网、限流、拒单、部分成交、进程重启和恢复演练。

## 后续评审入口

满足以上条件后，先选一个具有沙箱环境的执行通道实现，不同时接入多个市场。评审材料必须包含适配器协议、状态机、幂等策略、对账报告、故障演练结果、权限矩阵和回滚步骤；在材料齐全前不修改 `live_trading=false` 的默认值。
