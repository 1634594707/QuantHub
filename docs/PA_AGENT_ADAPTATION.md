# PA Agent 能力审计与 QuantHub 适配

本文记录 QuantHub 对 [PA_Agent](https://github.com/rosemarycox5334-debug/PA_Agent) 的持续参考范围，避免重复页面、无边界移植和不可审计的 AI 交易结论。

本轮审计基于上游提交 `3ab6c6ed9cb707c564f1e22bfdcf678ece13964b`（2026-07-27）。QuantHub 按自身领域模型重新实现适用能力，不引入上游桌面 GUI 或下单链路。

## 已有能力

QuantHub 在本轮之前已经具备：

- ATR14、EMA20 与倒序 K 线编号；
- 市场诊断到交易决策的两阶段 LLM 编排；
- 阶段一闸门短路；
- DeepSeek、OpenAI 和兼容 API 的统一客户端；
- 价格结构结果写入 `research_run`；
- 信号审核、模拟订单和账户账本链路。

因此没有新增 PA 一级页面、独立模型设置、独立成交记录或第二套信号中心。

## 本轮适配

### 输出质量闸门

新增 `strategies/ai_analysis/pa_agent/validation.py`，在 LLM 输出进入视图与信号链路前检查：

| 层级 | 检查内容 |
| --- | --- |
| 结构 | JSON 对象、必填字段、对象与数组类型 |
| 枚举 | 周期、方向、闸门、订单类型与终局 |
| 概率 | 单项范围、概率总和、方向是否对应最高概率 |
| 不变量 | `不下单` 时价格和方向字段必须为空 |
| 一致性 | 下单与终局、阶段一与阶段二摘要 |
| 风险 | 多空价格几何、最低 1:1 盈亏比、胜率与盈亏比正期望约束 |

错误分为阻断与警告。阻断错误会形成字段级反馈，最多触发一次低温重试；第二次仍失败则分析失败，不生成信号。每阶段校验结果、输出次数和警告随模型证据写入研究记录。

### 交易质量分析

参考交易报告的信息组织方式，在现有“执行 → 账户账本 → 绩效”中增加 `/ledger/trade-analytics`：

- FIFO 配对部分平仓、完整平仓和反向持仓；
- 只用闭合交易计算胜率、利润因子和平均盈亏比；
- 累计盈亏、连续亏损与未创新高时长；
- 月度盈亏、盈亏日历、多空质量和持仓时间分布；
- 总费用、平均费用和费用侵蚀；
- 未闭合批次数量与数量覆盖。

当前账本没有“预期成交价”，因此页面明确标记滑点不可用，不根据成交价臆造执行质量。

## 未迁移能力

| 上游能力 | 处理方式 | 原因 |
| --- | --- | --- |
| PyQt 桌面 GUI | 不迁移 | QuantHub 使用 React 工作台 |
| 独立模型设置 | 不迁移 | 已由系统设置统一管理 |
| 自动下单与券商连接 | 不迁移 | 当前只允许人工审核与模拟执行 |
| 自由追问窗口 | 暂不迁移 | 先保证结构化研究证据可审计 |
| 经验库 | 暂不迁移 | 需要先定义样本版本、检索隔离和泄漏边界 |
| 跨轮决策连续性 | 后续评估 | 需要与 `research_run` 版本和数据快照一致性共同设计 |
| 逐 K 线语义引用检查 | 后续评估 | 需要稳定的 K 线引用契约和更多回归样本 |

## 验证边界

- AI 校验只验证机器可判断的一致性，不证明行情判断正确。
- 交易质量只描述账本历史，不代表未来收益。
- 因子是否可用继续由样本外因子验证决定，PA 置信度不能替代 IC、回撤和成本检验。
- 所有交易动作继续进入信号审核和模拟交易，不因 AI 校验通过而自动执行。
