# QuantHub 功能边界

本文定义产品能力的唯一归属，避免同一算法、工作流或结果在多个一级入口重复实现。

## 主流程

```text
标的与数据 -> 综合评估 / 因子验证 -> 策略实验 -> 信号审核 -> 模拟交易 -> 账户账本
                                      \-> 策略运行 -> 策略组合

作业调度、运行故障、成员权限和系统设置为横向运营能力。
```

## 一级能力清单

| 工作区 | 一级能力 | 唯一职责 | 不负责 |
| --- | --- | --- | --- |
| 驾驶舱 | 总览 | 汇总账户、市场、研究、信号和故障状态 | 创建研究算法或执行订单 |
| 研究 | 综合评估 | 单标的研究编排与证据归档 | 因子样本外筛选、策略版本管理 |
| 研究 | 因子验证 | 因子 IC、稳定性、衰减、样本外收益、回撤验证与受约束 AI 科研复核 | 新闻解释、信号直接执行 |
| 研究 | 研究任务 | 查看、取消和重试异步研究作业 | 承载研究结果正文 |
| 策略 | 策略运行 | 已安装策略的参数、单次运行、传统回测和实时状态 | 维护实验版本树 |
| 策略 | 策略实验 | 策略定义、版本、实验、可复现运行和结果对比 | 直接发布交易订单 |
| 策略 | 策略组合 | 已验证策略的权重和启停配置 | 重新计算因子或策略回测 |
| 执行 | 信号审核 | 审核、拒绝或转换研究与策略信号 | 生成重复研究结论 |
| 执行 | 模拟交易 | 模拟订单、成交和账本同步 | 连接真实券商 |
| 执行 | 账户账本 | 现金、成交、持仓、绩效、闭合交易质量、归因和修正 | 充当订单状态机或虚构账本没有的滑点数据 |
| 执行 | 价格提醒 | 标的价格、涨跌和波动规则 | 作业失败告警 |
| 运营 | 标的与数据 | Instrument 主数据登记与数据源检查 | 单标的研究 |
| 运营 | 作业调度 | 定时任务配置、运行历史和作业告警 | 价格提醒 |
| 运营 | 运行故障 | 汇总研究、数据、作业和账本同步故障 | 重复保存各域业务数据 |
| 运营 | 成员权限 | 用户、角色、令牌和访问审计 | 系统运行参数 |
| 运营 | 系统设置 | AI、数据源、通知、备份和本地偏好 | 研究与执行业务操作 |

## 综合评估内部模块

综合评估是唯一的单标的研究入口。它编排以下模块并把证据写入同一 `research_run`：

| 模块 | 计算职责 | AI 边界 | 对外形态 |
| --- | --- | --- | --- |
| 量化快照 | 趋势、动量、波动、回撤、均值偏离和量价状态 | 不依赖 LLM | 综合报告的结构化量化证据 |
| 新闻 AI | 新闻情绪、主题、实体和事件摘要 | LLM 只增强非结构化证据 | 综合评估的“新闻证据”视图 |
| 价格结构 AI | K 线结构、关键位置和失效条件 | AI 负责价格行为推理 | 综合评估的“价格结构”视图 |
| 模型共识 | 聚合多个算法的方向、分歧和置信度 | 不把 LLM 文本当成价格事实 | 综合评估的“模型共识”视图 |
| 报告 | 汇总成功模块、保留分歧并形成可解释结论 | 不新增独立交易判断 | 评估记录与导出报告 |

`/news`、`/pa` 和 `/ensemble` 保留为兼容路由及模块调试入口，但不再出现在一级导航中。新产品流程不得再为它们创建第二套单标的入口。

## 综合评估与因子验证

两者使用部分相同的基础行情指标，但问题不同，因此保留为两个一级研究能力：

| 维度 | 综合评估 | 因子验证 |
| --- | --- | --- |
| 目标 | 解释当前标的状态 | 判断候选因子是否具有样本外预测力 |
| 数据划分 | 当前快照与历史证据 | 训练、隔离、样本外验证 |
| 输出 | 结论、证据、分歧、观察条件 | IC、ICIR、衰减、稳定性、组合收益与回撤 |
| AI 使用 | 新闻与价格结构推理 | 后续只能用于候选生成、状态识别和组合增强 |
| 下游 | 信号审核或继续观察 | 策略实验，不直接下单 |

基础指标计算只保留确定性实现。高级 AI 不能重复实现 RSI、MACD、ADX、ATR 等指标，也不能绕过样本外验证直接改变因子状态。

因子验证完成后可显式启动 AI 科研复核。服务端读取同一研究记录中已保存的统计快照，只向模型发送压缩后的结构化指标；仅旧版未提供运行 ID 的兼容调用会重新计算。AI 负责深审实际入选因子，并结合完整筛选概览检查过拟合风险、样本量、IC 衰减、成本敏感度、市场状态依赖和后续可证伪实验。输出须通过固定 schema、枚举、条数与因子键校验，最多自动修正一次。程序生成的 `可用 / 观察 / 淘汰` 状态在 AI 输出中保持锁定，AI 冲突只能作为审阅意见展示。高级推理调用采用单次 120 秒超时且禁用 SDK 传输重试，避免慢模型被过早中断或重复计费。

因子验证的新手摘要与专业详情必须使用同一份统计结果。摘要只负责组织结论、依据、风险、失效条件和后续动作；IC、ICIR、CVaR、回撤曲线与方法排名仍保留在可展开专业详情中。历史比较只读取已保存快照，不重新计算或改变原记录。

因子验证中的短线、波段和中线是研究周期模板；稳健验证、趋势研究和回撤检查是研究目的模板。两者都只映射到现有参数，不建立第二套研究算法。示例报告是只读学习材料，不写入真实研究历史；术语解释与首次阅读引导只改变信息呈现，不改变统计口径。

## 结果定位与回链

`research_runs` 仍是研究结果的唯一真值。研究任务、作业调度、提醒、信号和全局检索只保存或传递结果类型与记录 ID，并通过统一导航规则返回结果所属页面：`factor_research` 进入因子验证，其余综合研究进入综合评估历史。作业调度和运行故障不得复制研究正文。

使用质量指标只允许在本机记录固定白名单字段：事件名、页面、步骤、时间、耗时和错误分类。禁止写入标的、API Key、访问令牌、持仓明细、研究业务载荷或敏感模型配置。

价格结构 AI 的模型输出必须先经过确定性质量闸门。闸门负责结构、枚举、概率总和、空单字段、终局一致性、止损/入场/目标几何和期望约束；可修复错误只允许有限次分类反馈重试。未通过闸门的输出不得发布为信号。

## 账户账本与交易质量

交易质量分析是账户账本的绩效视图，不是新的一级报告产品。它只从账本成交流水按 FIFO 配对闭合交易，计算胜率、利润因子、平均盈亏比、连续亏损、持仓时间、多空差异、月度/日度盈亏与费用侵蚀。未闭合批次单独展示，不计入胜率。

账本未记录预期成交价时不得估算或展示滑点；后续若需要滑点分析，应先在模拟成交和账本同步契约中持久化预期价格，再扩展现有绩效视图。

## 策略运行与策略实验

策略运行面向已安装插件，保留快速参数运行、插件自带回测和运行状态。策略实验面向研发过程，负责定义、版本、实验、可复现运行和横向比较。新的版本管理、实验比较和参数搜索只能进入策略实验；策略运行页不得再新增第二套版本树。

## 模拟实验室兼容边界

`/demo-lab` 曾在一个表单内同时选择内置因子与内置策略，并通过 `/simulation/demo/*` 生成独立 JSON 运行记录。职责审计结果如下：

| 维度 | 旧模拟实验室 | 唯一归属 |
| --- | --- | --- |
| 输入 | 行情来源、标的、周期、因子、因子参数 | 因子候选与参数归因子工厂；已安装策略参数归策略运行；版本定义归策略实验 |
| 核心计算 | 因子跟随、均线与买入持有回测 | 因子有效性计算归因子工厂；插件回测归策略运行；可复现实验对比归策略实验 |
| 输出 | 收益、回撤、成交、日志、可复现凭据 | 分别写回拥有该运行的因子记录、策略运行或策略实验记录 |
| 持久化 | `data/demo_runs/*.json` | 仅作为历史兼容记录保留，不再接收新产品运行 |

因此 `/demo-lab` 不属于固定交易导航，也不再创建新回测。它保留为只读兼容入口，用于回读原有 `data/demo_runs` 记录。新因子验证从 `/factor-research` 发起，已安装策略回测从 `/strategies` 发起，策略定义、版本与横向比较从 `/strategy-lab` 发起。旧 API 暂时保留以恢复历史记录，但不得作为新界面的运行入口。

## 告警边界

价格提醒属于执行域，监控市场条件。作业告警属于运营域，监控调度和任务失败。运行故障只聚合异常并提供恢复动作，不复制价格提醒或作业调度的配置界面。

## 新功能准入规则

新增功能前必须回答四个问题：

1. 它在主流程中属于哪个阶段？
2. 哪个现有一级能力拥有它的数据和状态？
3. 它是新的计算能力、已有能力的新视图，还是兼容入口？
4. 是否已经存在相同输入、相同计算和相同输出的页面或 API？

如果输入、核心计算和输出三者均相同，应扩展现有能力，不得新增一级页面。只有数据所有权、验证方法或下游动作明确不同时，才允许建立独立能力。
